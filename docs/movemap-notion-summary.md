# 무브맵 프로젝트 정리

## 1. 프로젝트 한 줄 설명

무브맵은 물리치료사가 운영하는 운동센터를 지도에서 찾을 수 있는 웹/모바일 서비스다.

센터장은 직접 센터를 등록하고, 관리자는 승인하며, 사용자는 지도에서 가까운 센터를 찾고 상세 정보를 확인할 수 있다.

---

## 2. 왜 만들고 있는가

현재 대한민국에서 도수치료가 관리급여화되는 흐름 속에서 물리치료사들이 병원 밖으로 나와 운동센터를 여는 경우가 늘고 있다.

하지만 센터장 입장에서는 홍보가 어렵고, 일반 사용자는 물리치료사가 운영하는 센터를 찾기 어렵다.

무브맵은 이 문제를 해결하기 위한 지도 기반 검색 서비스다.

---

## 3. 현재 MVP 상태

현재는 로컬 MVP 상태다.

```text
웹사이트: http://localhost:8080/web/
API 서버: http://localhost:8090
모바일 앱: Expo Go 테스트
지도: 네이버 지도 API
데이터: 로컬 서버/JSON 기반
```

이 상태는 내 맥북에서 테스트하는 단계다.  
실제 출시를 위해서는 GitHub, DB, 웹 배포, 앱 빌드가 필요하다.

---

## 4. 지금까지 만든 기능

### 사용자 웹사이트

- 무브맵 메인 웹페이지
- 네이버 지도 연동
- 센터 목록 표시
- 센터 검색/필터
- 지도 클러스터 표시
- 확대 시 개별 센터 마커 표시
- 센터 클릭 시 상세 정보 표시
- 센터 상세 카드 우하단 고정
- 센터 상세가 떠 있어도 추천센터 목록 끝까지 스크롤 가능
- 지도와 센터 목록 스크롤 분리
- 지도 위 스크롤은 확대/축소
- 센터 목록 위 스크롤은 목록만 이동

### 모바일 앱

- Expo 기반 iOS/Android 공통 앱
- 네이버 지도 WebView 연동
- 센터 목록 표시
- 센터 클릭 시 지도 위치로 자동 이동
- 센터 클릭 시 하단 상세 카드 표시
- 지도 빈 곳 클릭 시 상세 카드가 아래로 내려가며 사라짐
- 하단 상세 카드 높이 축소
- 웹과 동일한 센터 데이터 사용

### 센터 등록/관리 흐름

- 센터장 등록 페이지 MVP
- 상세 주소 입력
- 네이버 지도 검색 링크 연결
- 사진 입력/업로드 영역
- 물리치료사 면허 인증 입력 영역
- 관리자 승인 후 메인 웹/앱에 자동 노출되는 흐름 설계

### 관리자/데이터 흐름

- 센터 승인 개념 구현
- 승인된 센터만 지도에 표시
- 조회/클릭 이벤트 기록 개념 설계
- 향후 관리자 페이지에서 조회수 확인 가능하도록 방향 설정

## 5. 현재 중요한 기술 결정

### 지도

네이버 지도 API를 사용한다.

현재 사용 중인 네이버 지도 Client ID:

```text
lae0rqg0zj
```

출시 시 네이버 클라우드 콘솔에 실제 도메인과 앱 정보를 등록해야 한다.

### 모바일 앱

Expo React Native를 사용한다.

하나의 모바일 코드로 iOS와 Android를 같이 만든다.

```text
mobile/ 코드 1개
→ iOS 앱
→ Android 앱
```

### 추천 배포 구조

```text
GitHub
= 코드 보관소

Vercel
= 웹사이트 배포

Supabase
= DB, 로그인, 사진 저장

Expo/EAS
= iOS/Android 앱 빌드

Naver Cloud
= 지도 API
```

## 6. GitHub 운영 방식

GitHub는 서버가 아니라 코드 보관소다.

추천 방식은 하나의 GitHub 저장소 안에 여러 폴더를 나누는 것이다.

```text
movemap/
  web/
  mobile/
  admin/
  register/
  server/
  shared/
  database/
  docs/
```

GitHub 저장소는 하나로 시작하는 것이 좋다.

```text
GitHub 저장소 1개
폴더는 역할별로 여러 개
배포는 각 폴더별로 따로
```

## 8. 출시까지 해야 할 일

### 1단계. 로컬 MVP 정리

현재 `outputs` 안에 있는 파일들을 출시용 폴더 구조로 정리한다.

목표:

```text
웹, 모바일, 관리자, 등록, 서버, DB를 구분하기
```

### 2단계. 로컬 주소 제거

현재 코드에는 아래 주소가 들어가 있다.

```text
localhost
127.0.0.1
192.168.150.139
```

출시 시 아래처럼 실제 주소로 바꿔야 한다.

```text
https://movemap.kr
https://api.movemap.kr
```

주소는 코드에 직접 박지 않고 환경변수로 관리하는 것이 좋다.

### 3단계. GitHub 저장소 생성

정리된 프로젝트 전체를 GitHub에 올린다.

GitHub 역할:

- 코드 보관
- 버전 관리
- Codex 수정 반영
- 배포 서비스와 연결

### 4단계. Supabase 연결

로컬 JSON 대신 실제 DB를 사용한다.

Supabase에서 필요한 것:

- 센터 정보 저장
- 센터 신청 저장
- 사진 저장
- 면허 인증 파일 저장
- 관리자 로그인
- 조회수/클릭 로그 저장

### 5단계. 웹 배포

Vercel에 웹사이트를 올린다.

예:

```text
https://movemap.kr
https://movemap.kr/register
https://movemap.kr/admin
```

### 6단계. 네이버 지도 운영 설정

네이버 클라우드에서 실제 서비스 환경을 등록한다.

필요한 것:

```text
Web 서비스 URL: https://movemap.kr
Android Package: com.movemap.app
iOS Bundle ID: com.movemap.app
```

### 7단계. 앱 빌드

Expo EAS로 앱스토어용 앱을 빌드한다.

```text
iOS → App Store Connect
Android → Google Play Console
```

### 8단계. 심사 제출

필요한 계정:

- Apple Developer Program
- Google Play Console
- Expo 계정

필요한 문서:

- 개인정보처리방침
- 이용약관
- 위치정보 관련 안내

## 9. 출시 후 업데이트 방식

출시 후에도 Codex로 계속 수정할 수 있다.

기본 흐름:

```text
1. Codex에게 수정 요청
2. 로컬 코드 수정
3. 로컬 테스트
4. GitHub에 업로드
5. 배포 서비스가 반영
6. 실제 웹/앱에서 확인
```

중요한 점:

운영 서버에서 직접 코드를 고치는 것이 아니라, GitHub의 원본 코드를 수정하고 배포한다.

---

## 10. 웹과 모바일을 같이 업데이트하는 방법

데이터는 한 번만 수정하면 된다.

예:

```text
센터 이름 변경
센터 사진 변경
센터 승인
가격 변경
주소 변경
```

이런 정보는 Supabase DB에 저장되므로 한 번 수정하면 웹과 앱이 같이 바뀐다.

화면 디자인은 웹과 모바일 코드가 다르므로 둘 다 수정해야 한다.

하지만 Codex에게 한 번에 요청하면 된다.

예:

```text
센터 상세 카드 디자인을 바꿔줘.
웹과 모바일 둘 다 같은 느낌으로 반영해줘.
```

## 11. 업데이트 종류별 배포 방식

### 웹 업데이트

```text
로컬 수정
→ GitHub 업로드
→ Vercel 자동 배포
→ 웹사이트 반영
```

빠르게 반영 가능하다.

### 모바일 앱 업데이트

간단한 화면/문구/UI 수정:

```text
로컬 수정
→ GitHub 업로드
→ Expo Updates
→ 앱에 빠르게 반영
```

앱스토어 심사가 필요한 수정:

```text
권한 추가
앱 이름 변경
아이콘 변경
푸시 알림
결제
네이티브 기능 추가
```

이 경우:

```text
EAS Build
→ App Store / Play Store 심사
→ 사용자 업데이트
```

### 서버/DB 업데이트

```text
로컬 수정
→ 테스트
→ GitHub 업로드
→ 서버 배포
→ DB 마이그레이션
```

DB 변경은 운영 데이터가 있으므로 조심해야 한다.
