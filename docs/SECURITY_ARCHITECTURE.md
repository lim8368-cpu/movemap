# Movemap Security Architecture

이 문서는 환자 개인정보와 건강정보를 다루는 운영 버전을 만들 때 지켜야 할 기준입니다.
현재 저장소의 로컬 MVP는 실제 환자정보 저장용이 아닙니다.

## 핵심 구조

```text
iPhone 앱 / Android 앱 / Web
   │ HTTPS
   ▼
API 서버
   │
   ├─ 인증·권한 검사
   ├─ 요청 검증
   ├─ 접속기록 저장
   └─ 암호화·복호화
          │
          ▼
     암호화된 데이터베이스

사진·문서 → 비공개 파일 저장소
암호화 키 → 별도 비밀관리 서비스
```

이 구조를 무브맵의 운영 보안 기본 구조로 사용합니다.

앱은 운영 데이터베이스에 직접 접속하지 않습니다. 모든 개인정보와 건강정보 접근은 API 서버를 거칩니다.

## 구성 요소별 책임

### iPhone 앱 / Android 앱 / Web

앱과 웹은 화면 표시와 사용자 입력만 담당합니다.

- 운영 DB 주소를 알면 안 됩니다.
- DB 비밀번호나 API 비밀키를 포함하면 안 됩니다.
- 인증 토큰만 가지고 API 서버에 요청합니다.
- iOS 앱의 인증 토큰은 `UserDefaults`가 아니라 Keychain 또는 Expo SecureStore에 저장합니다.
- 모든 API 요청은 HTTPS만 사용합니다.

### API 서버

API 서버는 개인정보 접근의 유일한 입구입니다.

API 서버가 반드시 처리해야 하는 일:

- 로그인 사용자인지 확인
- 사용자의 역할 확인
- 사용자의 `organizationId` 확인
- 담당 환자 관계 확인
- 요청값 검증
- 객체 수준 권한검사
- 감사 로그 저장
- 접속기록 저장
- 환자 민감 필드 암호화
- 필요한 경우에만 복호화
- DB 오류, stack trace, 비밀값, 개인정보가 응답에 노출되지 않도록 차단

### 암호화된 데이터베이스

운영 데이터베이스는 서버에서만 접근합니다.

- 환자 기본 식별자는 UUID를 사용합니다.
- 주민등록번호는 저장하지 않습니다.
- 환자 이름, 연락처, 생년월일, 진단명, 치료 메모는 AES-256-GCM으로 암호화해서 저장합니다.
- DB 자체 암호화와 백업 암호화도 켭니다.
- 개발/테스트/운영 DB는 완전히 분리합니다.

### 비공개 파일 저장소

환자 사진, 문서, 첨부파일은 DB에 base64로 저장하지 않습니다.

- 비공개 버킷에 저장합니다.
- 파일명은 UUID 기반 무작위 이름을 사용합니다.
- 확장자, MIME type, 크기를 검증합니다.
- 앱에서 파일을 열 때는 짧은 유효기간의 signed URL만 발급합니다.
- 환자 삭제 또는 계정 삭제 시 관련 파일도 함께 삭제합니다.

### 비밀관리 서비스

암호화 키와 운영 비밀값은 GitHub, 앱 번들, `.env`에 넣지 않습니다.

비밀관리 서비스에 넣을 값:

- AES-256-GCM 암호화 키
- DB 접속 문자열
- API 비밀키
- 세션 서명 키
- 파일 저장소 접근 키

예시 서비스:

- Naver Cloud Secret Manager
- AWS Secrets Manager
- GCP Secret Manager
- Azure Key Vault

## 데이터 흐름

환자정보 조회 예시:

```text
1. iPhone 앱이 HTTPS로 API 서버에 요청
2. API 서버가 access token 확인
3. API 서버가 사용자 역할 확인
4. API 서버가 organizationId 확인
5. API 서버가 담당 환자 관계 확인
6. API 서버가 감사 로그 기록
7. API 서버가 DB에서 암호화된 환자정보 조회
8. API 서버가 필요한 필드만 복호화
9. API 서버가 사용자 권한에 맞는 응답만 반환
```

환자 파일 열람 예시:

```text
1. 앱이 파일 열람 요청
2. API 서버가 인증·권한·담당 관계 확인
3. API 서버가 감사 로그 기록
4. API 서버가 비공개 저장소에 signed URL 생성 요청
5. 앱은 짧은 시간만 유효한 URL로 파일 열람
```

## 접속기록

서버는 API 요청과 주요 페이지 접속을 기록합니다.

기록하는 항목:

- 접속 시간
- 사용자 ID
- 사용자 역할
- 조직 ID
- 접속 출처: `web`, `mobile-app`, `mobile-map`, `admin`, `register`
- 요청 method와 path
- 응답 상태 코드
- IP
- 기기/브라우저 정보

접속기록에 저장하면 안 되는 항목:

- 비밀번호
- access token
- refresh token
- 환자 이름
- 진단명
- 치료 메모
- 파일 원본 URL

최고관리자 `super_admin`만 접속기록을 조회할 수 있습니다.
일반 관리자, 물리치료사, 접수 직원, 조회 전용 역할은 접속기록을 볼 수 없습니다.

## 역할

- `admin`: 조직 관리, 권한 관리, 환자 데이터 관리
- `therapist`: 본인이 담당하는 환자 조회 및 치료 메모 작성
- `front_desk`: 접수와 예약에 필요한 최소 환자정보만 접근
- `read_only`: 허용된 범위의 조회만 가능

서버는 인증과 권한을 분리해서 검사합니다.

## 환자 접근 규칙

환자 데이터 접근은 환자 UUID만으로 허용하지 않습니다.
서버는 항상 다음 값을 함께 확인해야 합니다.

- 현재 사용자 ID
- 현재 사용자의 `organizationId`
- 현재 사용자의 역할
- 현재 사용자와 환자의 담당 관계
- 요청한 작업의 권한

다른 환자의 UUID를 URL에 넣어도 조회, 수정, 삭제가 되면 안 됩니다.

## 암호화 대상

다음 필드는 애플리케이션 수준에서 AES-256-GCM으로 암호화합니다.

- 환자 이름
- 연락처
- 생년월일
- 진단명
- 치료 메모

암호화 키는 `.env`, 앱 번들, Git 저장소에 넣지 않습니다.
AWS Secrets Manager, GCP Secret Manager, Naver Cloud Secret Manager 같은 클라우드 비밀관리 서비스에 저장합니다.

## 파일 저장

환자 파일과 사진은 공개 URL로 저장하지 않습니다.

- 비공개 버킷 사용
- 짧은 유효기간의 signed URL 발급
- 확장자, MIME type, 파일 크기 검증
- 무작위 파일명 사용
- 환자/계정 삭제 시 관련 파일 함께 삭제

## 로컬 MVP 제한

현재 `server/data/db.json`은 로컬 테스트용입니다.
운영에서는 실제 환자정보, 면허증 이미지, 연락처, 건강정보를 이 파일에 저장하면 안 됩니다.

운영 전환 시 필수 변경:

1. 운영 DB로 이전
2. 비밀관리 서비스 연결
3. HTTPS 배포
4. 인증 공급자 또는 Argon2id/bcrypt 기반 비밀번호 저장
5. 파일 비공개 저장소 연결
6. 권한 우회 및 ID 조작 테스트 통과
